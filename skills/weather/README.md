# Погода

## Описание

Обычный навык `weather`. Регистрация — `protocol.Run`: своего звука и управления воспроизведением нет.

Инструмент отвечает текущей погодой по-русски. Аргументы — `city` и `country`. Пустой город берёт сохранённое место. Если места ещё нет, ответ: «В какой стране и в каком городе смотреть погоду?», к API навык не ходит. Город вместе со страной становится местом по умолчанию. Только город — погода на один раз, сохранённое место не меняется.

Подсказки маршрутизации: «погод», «температур», «дождь», «градус».

## Состояние

Данные — `skills/weather/data/place.json`. Поля: `country`, `city`, `latitude`, `longitude`, `asks_day` (локальная дата `YYYY-MM-DD`), `asks_count`. Каталог по умолчанию — `skills/weather`. Путь с суффиксом `.db` — старая база: она только читается, место пишется в `place.json` рядом с файлом.

Удачная фраза: «В городе %s сейчас %s и %s» — город, температура словами, состояние. Следом вторая строка `asks_today: N`: сколько раз сегодня погоду уже спросили. Счётчик нужен для подкола. Навык отдаёт число, фразу подкола не составляет. Счёт растёт только после удачной фразы. Другой локальный день начинает с 1. Запись нового города дневной счётчик не сбрасывает.

Источник — Open-Meteo без ключа. Геокодинг `https://geocoding-api.open-meteo.com`, текущая погода `https://api.open-meteo.com`. Таймаут по умолчанию 8 секунд.

## Разработано

- Один инструмент `weather` и одно место по умолчанию.
- Геокодинг `GET /v1/search`: имя города, язык `ru`, до 5 результатов. Страна сверяется с именем, кодом и фиксированными алиасами (Россия, РФ, Russia, Казахстан, Беларусь и другие). Нет совпадения — «Не нашла такой город.»
- Текущие условия `GET /v1/forecast`: `temperature_2m`, `weather_code`, `precipitation`, единица `celsius`, часовой пояс `auto`. Ключ не передаётся.
- Температура округляется до целого и говорится по-русски, отрицательная — со словом «минус». Состояния: ясно (0), малооблачно (1), облачно (2), пасмурно (3), туман (45, 48), идёт снег, гроза, ледяной дождь, идёт дождь. Иной код без осадков — «без осадков». Осадки от 0.1 выбирают мокрую формулировку. Пустое имя города в фразе заменяется на «этом городе».
- Сбой API, таймаут и неразобранные аргументы — «Не удалось узнать погоду.» Неизвестный `provider` — «Источник погоды не настроен.» Ошибка записи места — «Не удалось запомнить город.»
- Настройки берутся из `skills.weather` в `config.yml`: провайдер, адреса геокодинга и прогноза, каталог и таймаут.
- При открытии `skills/weather` старый `data/skills.json` копируется один раз. Место из `data/variacore.db` переносится в `place.json`, если файла ещё нет. Уже записанный `place.json` повторно не затирается.

## Проверено

Ниже только утверждения тестов репозитория.

Пакет `skills/weather`:

- `TestSpeakSentenceUnchanged` и `TestForecastSpeaksTemperatureWords`: для Кирова и кода 45 фраза «В городе Киров сейчас минус один и туман»; отдельно 0 → «ноль», 2 → «два», 21 → «двадцать один». К фразе дописывается `asks_today: 1`.
- `TestNoPlaceAsksAndSkipsForecast`: пустые `city` и `country` через `Handle` дают «В какой стране и в каком городе смотреть погоду?». Геокодинг и прогноз не вызываются.
- `TestSavePlaceThenEmptyCityUsesCoordinates`: «Казань» и «Россия» дают «В городе Казань сейчас два и пасмурно» и `asks_today: 1` (мок прогноза без явной температуры отдаёт 2.4 и код 3). В геокодинг уходит имя «Казань», в прогноз — широта 55.79 и долгота 49.12. В документе ровно ключи `country`, `city`, `latitude`, `longitude`, `asks_day`, `asks_count`. Второй вызов с пустым городом геокодинг не повторяет, прогноз идёт второй раз с теми же координатами, `asks_today: 2`.
- `TestSecondCallUsesDatabase`: после закрытия новый экземпляр на том же пути читает Москву (55.75, 37.62). Город из пробелов считается пустым. Геокодинг не повторяется, фраза про Москву с `asks_today: 2`.
- `TestExplicitCityDoesNotReplaceSavedPlace`: после Москвы вызов «Казань» без страны говорит про Казань и координаты 55.79, 49.12, сохранённый город остаётся Москвой. Следующий пустой вызов снова запрашивает 55.75, 37.62.
- `TestAPIErrorIsRussian`: прогноз с кодом 502 возвращает ровно «Не удалось узнать погоду.». В строке нет `http` и `://`.
- `TestClientUsesConfigTimeoutAndBaseURL`: таймаут клиента и базы геокодинга и прогноза равны переданным настройкам. Успешный вызов ходит на `/v1/search` и `/v1/forecast`. При таймауте 200 мс и задержке прогноза 3 с ответ — «Не удалось узнать погоду.», ожидание короче 2 с, медленный обработчик при этом вызван.
- `TestSettingsFromEnv`: из окружения читаются `http://api.test`, `http://geo.test`, `data/from-env.json`, provider `open-meteo`, таймаут 3.5 с.
- `TestLegacyPlaceCopiedOnOpen`: таблица sqlite `place` (Россия, Киров, 58.6, 49.66) при пустом городе даёт «В городе Киров сейчас минус один и туман» и `asks_today: 1` без геокодинга. Прогноз идёт по этим координатам, документ с ними совпадает. После закрытия строка в таблице `place` остаётся «Киров».
- `TestNoteAskResetsWhenDayChanges`: за `2026-11-06` счёт 1, затем 2; за `2026-11-07` снова 1. Город Киров и широта 58.6 на месте. `Save` Казани этот счёт не обнуляет: следующий `noteAsk` того же дня даёт 2, `Load` возвращает Казань.
- `TestAskCountFollowsLocalDay`: три успешных вопроса в текущий локальный день дают `asks_today` 1, 2 и 3 при одном геокодинге. `noteAsk` на дату через 48 часов возвращает 1, город остаётся Казанью.

Пакет `internal/skillstate`, файл места погоды:

- `TestLegacyPlaceCopiedOnce`: таблица `place` копируется в `data/place.json` один раз. Повторный импорт не затирает уже записанную Казань. Обновление города в sqlite до Москвы в базе остаётся, в `place.json` не попадает.
- `TestExistingPlaceSkipsLegacyDatabase`: если `place.json` уже есть, база с Кировом его не заменяет.
- `TestSiblingDatabaseImportsPlace`: документ `skill_state` с именем `weather` из `data/variacore.db` становится местом (Киров, 58.6, 49.66).
- `TestWeatherSkillDirImportsDataDatabase`: каталог `skills/weather` забирает таблицу `place` из `data/variacore.db` в `skills/weather/data/place.json` (Киров, 58.59809, 49.65783).
- `TestMigrateSharedCopiesAndLeavesTheOldFile`: ключ `weather` из `data/skills.json` копируется в `skills/weather/data/place.json`. Старый файл не меняется. Повторная миграция не возвращает Киров поверх уже записанной Казани.

## Не реализовано

- Погода на другой час или другой день. Запрос читает только блок `current`.
- Больше одного сохранённого города.
- Рабочий источник кроме `open-meteo`. Другое имя provider отвечает «Источник погоды не настроен.»
- Текст подкола. Навык пишет только число `asks_today`.
- Ветер, влажность, давление, ощущаемая температура и величина осадков во фразе. Осадки только выбирают слова о дожде, снеге, грозе или ледяном дожде.
