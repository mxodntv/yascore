# YouTube Music

## Описание

Медиаскилл `youtubemusic`. `Register` вызывает `protocol.RunMedia`: у скилла есть звук и флаг media, средняя кнопка может его продолжить. На колонке играет плеер по SSH. Хост, порт, пользователь, бинарь и адрес сервиса берутся из `skills.youtube_music` в `config.yml`.

Инструменты: `play_music` (`query`, обязательный `kind`) и `music_control` (`action`: pause, resume, next, previous, stop, status, like, unlike). Подсказки: «ютуб», «youtube», «музык», «песн», «трек», «плейлист», «альбом», «включи», «поставь», «пауза», «стоп», «следующ», «предыдущ», «назад», «дальше», «радио», «лайк», «нравится», «похож».

Включение по названию ищет трек и ставит `https://music.youtube.com/watch?v=…`. Из выдачи берётся совпадение по словам запроса; в названии понижаются 8-bit, instrumental, karaoke, cover и похожие пометки. Если поиск пустой, в плеер уходит сама фраза. Плейлист с id `PL…` или `RD…` становится ссылкой на playlist. Альбом, исполнитель и радио уходят фразой как есть. Старт повторяется один раз, если плеер сразу отвечает «не играет».

`kind=any` с пустым запросом или с «музыка» / «что-нибудь» / «любую» продолжает остановленную очередь плеера. Если звук уже идёт, скилл сообщает, что играет. Пустая очередь запускает подборку: сначала «мои лайки» плеера, затем `recommendations`.

Тихий успех — ответ `[[varya:silent]]`. Так заканчиваются пауза, стоп, лайк, снятие лайка и переход к уже сохранённому соседнему треку. Колонка эту метку не произносит.

«Назад» и «дальше» при живой локальной истории включают соседний трек по названию тем же поиском. Текущий при шаге назад остаётся следующим в списке. Если соседа в истории нет, уходит команда `previous` или `next` плеера. Пока следующий трек отложен, скилл раз в две секунды читает статус: после конца текущего (stopped или idle, либо другой трек уже играет) отложенный стартует сам. Пауза этот шаг не делает.

Лайки — локальный список. «Нравится» пишет текущий трек плеера или последний, который скилл уже запомнил. Повтор того же названия, исполнителя и сервиса обновляет `liked_at` и вторую строку не создаёт. `kind=likes` включает последний сохранённый трек. `kind=similar` ищет по исполнителю этого лайка, а если исполнителя нет — по названию. Пустой список отвечает «Пока ничего не нравится.» и плеер не вызывает.

История и лайки лежат в `data/yascore.db`, таблицы `youtubemusic_likes`, `youtubemusic_plays`, `youtubemusic_recent`. Сервис строки — `youtube-music`. История растёт дальше 20 треков. Рядом лежащий `musicplayer.db` читается один раз, только когда новые таблицы пустые и в старых `musicplayer_*` есть строки; старый файл остаётся. JSON `skills/youtube-music/data/likes.json`, `queue.json` и `history.json` копируются в те же таблицы один раз, пока они пустые, и тоже остаются на диске. Документ `youtubemusic` из `data/skills.json` перед этим раскладывается в эти JSON, если их ещё нет; общий файл не переписывается.

## Состояние

Скилл включён в процесс и ходит в `ytm-alice`. Рабочая база — `data/yascore.db` с префиксом `youtubemusic_`. `Open` создаёт эти таблицы. `musicplayer.db` — только источник одноразового копирования в соседний каталог той же базы.

Входа в аккаунт YouTube Music в коде нет. Без него личная библиотека плеера недоступна: голая просьба «включи музыку» при пустой очереди заканчивается фразой «не играет: личные подборки недоступны, пока YouTube Music не подключён, и остановленного трека нет». Локальные лайки этот вход не подменяют. Скачивания треков нет.

## Разработано

- Регистрация медиаскилла `youtubemusic` через `protocol.RunMedia`, инструменты `play_music` и `music_control`.
- Включение по названию: поиск, выбор id, play по ссылке `watch?v=`; плейлист, альбом, исполнитель и радио — фразой. Повтор старта, если поток сразу оборвался.
- `kind=any` без названия: продолжить остановленную очередь, оставить уже играющий трек, иначе подборка плеера. Отдельный resume пустую очередь в подборку не превращает и отвечает «нечего продолжать».
- Тихий успех `[[varya:silent]]` на паузе, стопе, лайке, снятии лайка и на previous/next по сохранённому названию. Удачный play по имени отвечает «играет …». Ошибка плеера остаётся текстом «не играет …».
- Локальные previous/next по названию и автостарт отложенного трека, когда текущий замолкает. До трёх попыток, если старт не удался.
- Лайки в `youtubemusic_likes` (`liked_at`, `last_played_at`), `kind=likes` и `kind=similar` по этому списку. Пустой список и отсутствие текущего трека — отдельные фразы, без поиска.
- История в `youtubemusic_plays` и указатель `youtubemusic_recent`. Потолка в 20 строк нет.
- Одноразовый перенос из `musicplayer.db` и из JSON скилла. `place.json` и чужие JSON навыков этот перенос не читает.
- Громкость 0–100 пишется в уже запущенный плеер. Пока помощник говорит, скилл сообщает последний выставленный уровень и играет ли звук.

## Проверено

Тесты пакета `skills/youtube-music`, с подменой SSH и временной SQLite. Живой сессии с колонкой в этих тестах нет.

- `main_test.go` — команда play для трека и плейлиста, пустой запрос отвергается; resume остановленной очереди даёт «играет …» и не зовёт подборку; пустая очередь на resume подборку не стартует; уже играющий трек даёт `[[varya:silent]]`; `next`, `previous` и алиас `prev`; строка громкости `volume 0.70`; playing и buffering считаются звуком, paused и stopped — нет.
- `match_test.go` — из поиска берётся оригинал, а не instrumental; статус «играет …» и «не играет …: аудиопоток прерван»; «музыку» — голый запрос, имя трека — нет; stopped с очередью → resume, playing → already, пустая очередь → mix; плейлист `PLtest` становится ссылкой; «включи песню Get Lucky» очищается до названия.
- `likes_test.go` — лайк текущего трека молча, вторая запись не плодит строку, `kind=likes` играет `watch?v=`; unlike молча снимает лайк; лайк только что сыгранного трека, когда плеер молчит; пустые likes и similar отвечают «Пока ничего не нравится.» без вызова плеера; similar ищет исполнителя или название из списка и не зовёт recommendations; лайк без id играется названием; previous/next без локальной истории шлют команду плеера и молчат; без трека — «Сейчас нечего лайкать.» Файл места погоды эти тесты не меняют.
- `queue_test.go` — Alpha, затем Beta: previous играет Alpha по названию и оставляет Beta следующим, next возвращает Beta; ответ в обоих случаях `[[varya:silent]]`. Конец Alpha запускает Beta, пауза не запускает. 21 трек остаётся в истории, лайк рядом сохраняется. Маркер тишины равен `[[varya:silent]]`, play отвечает «играет …», пауза — этим маркером.
- `store_test.go` — один лайк хранит оба времени, повтор обновляет `liked_at`; история из 21 строки, предыдущий заголовок — предпоследний; JSON likes/queue копируются в `yascore.db` один раз и не затирают `place.json`; строки `musicplayer.db` копируются один раз, старый файл остаётся; пустой `musicplayer.db` не мешает импорту JSON.
- `migrate_test.go` — документ `youtubemusic` из `data/skills.json` раскладывается в `likes.json`, `history.json` и `queue.json`; общий файл не меняется; повторная миграция уже записанный `likes.json` не перезаписывает.

## Не реализовано

- Вход в аккаунт YouTube Music. Личные подборки и «мои лайки» плеера без этого входа недоступны.
- Скачивание треков: mp3, wav, yt-dlp и каталог `music/` в коде скилла отсутствуют.
